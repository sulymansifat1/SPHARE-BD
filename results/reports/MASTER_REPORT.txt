1. PROBLEM STATEMENT AND ARCHITECTURAL SCOPE
================================================================================

A. The Forced-Classification Failure Mode:
Standard deep neural networks for vibration-based bearing fault diagnosis operate
predominantly under a closed-set, forced-classification paradigm. Given an arbitrary
vibration waveform, the model is compelled to output probabilities summing to 1 over
predefined training health states (e.g., Normal, Inner Race Fault, Outer Race Fault,
Ball Fault). When machines experience unlearned operating maneuvers (speed shifts, load
variations, or foreign kinematics), closed-set classifiers suffer catastrophic
overconfidence: they project out-of-support signals onto known health categories,
generating confident but completely erroneous fault classifications.

B. The Selective Diagnosis Formulation:
SPHARE-BD reformulates bearing diagnostics as a source-only selective classification
problem. Rather than forcing a fault prediction on every query, the framework evaluates
physical and kinematic support before allowing the classifier to execute:
    y_hat(x, c) = f_theta(x)  if A(x, c) == 1
    y_hat(x, c) = BOT          if A(x, c) == 0  (Safe Abstention)

C. Authoritative Two-Stage Decision Rule:
In SPHARE-BD Final Version, the hierarchical acceptance function A(x, c) is defined
strictly by TWO sequential, physical support gates:
    A(x, c) = g1(c) * g2(x, c)

where:
  1. g1(c) in {0, 1} is Stage 1: Operating-Condition / Telemetry Support Gate.
     Evaluates operational metadata c = [speed, load]^T against calibrated source
     operating bounds (2D Delaunay convex hull or axis-aligned bounding box).
  2. g2(x, c) in {0, 1} is Stage 2: Kinematic Order-Domain Spectral-Envelope Gate.
     Normalizes vibration into rotational orders (o = f / f_r) and screens an
     11-dimensional spectral energy descriptor against regional tolerance envelopes.

D. Sequential Short-Circuiting (Early-Exit Inference):
Inference operates hierarchically with strict short-circuiting:
  - If Stage 1 fails (g1(c) == 0): The framework immediately emits BOT and terminates
    in 0.14 ms CPU latency. Preprocessing, Stage 2, and the classifier are bypassed.
  - If Stage 1 passes (g1(c) == 1): Waveform x[n] is preprocessed and evaluated by Stage 2.
  - If Stage 2 fails (g2(x, c) == 0): The framework immediately emits BOT in 5.40 ms
    CPU latency. Classifier inference is bypassed.
  - If both pass (A(x, c) == 1): The frozen 1D-CNN diagnoses the waveform via window-level
    majority voting in 27.60 ms total CPU latency.

E. Rationale for Excising Stage 3:
In the earlier historical prototype, a third gate (Stage 3: local source manifold
consistency via Ledoit-Wolf covariance shrinkage) was included. Rigorous empirical
audit revealed that Stage 3 provided 0.0% unique out-of-distribution rejection benefit
(100% of unsupported shifts were already stopped by Stages 1 & 2), but caused 7 false
rejections per seed on valid supported SDUST records (depressing coverage to 66.7%).
Excising Stage 3 restored supported coverage to 90.00% with 100.0% accepted accuracy,
while preserving 0.00% false acceptance on all tested unsupported shifts.

4. METHODOLOGY & SPECIFICATION (SPHARE-BD FINAL VERSION)
================================================================================

A. Frozen 1D-CNN Fault Classifier (src/model.py):
  - Backbone: 4 Conv1D-BatchNorm-ReLU blocks with MaxPool1d and AdaptiveAvgPool1d:
      * Block 1: Conv1d(1, 16, k=64, s=8, p=28) -> BatchNorm1d(16) -> ReLU() -> MaxPool1d(2, 2)
                 Weights: 1,024 w + 16 b = 1,040 | Buffers: 32 affine + 32 running stats
      * Block 2: Conv1d(16, 32, k=3, s=1, p=1) -> BatchNorm1d(32) -> ReLU() -> MaxPool1d(2, 2)
                 Weights: 1,536 w + 32 b = 1,568 | Buffers: 64 affine + 64 running stats
      * Block 3: Conv1d(32, 64, k=3, s=1, p=1) -> BatchNorm1d(64) -> ReLU() -> MaxPool1d(2, 2)
                 Weights: 6,144 w + 64 b = 6,208 | Buffers: 128 affine + 128 running stats
      * Block 4: Conv1d(64, 128, k=3, s=1, p=1) -> BatchNorm1d(128) -> ReLU() -> AdaptiveAvgPool1d(1)
                 Weights: 24,576 w + 128 b = 24,704 | Buffers: 256 affine + 256 running stats
  - Classification Head:
      * Linear(128, 128) -> ReLU() | Weights: 16,384 w + 128 b = 16,512
      * Linear(128, 4)             | Weights: 512 w + 4 b = 516
  - Parameter Totals:
      * Trainable Parameters: 51,028 float32 weights
      * Persistent Buffers: 484 elements (running mean/variance)
      * Checkpoint size: 216,734 bytes on disk (.pt file)
  - Window Aggregation: Majority vote over all W = 102 windows per recording:
      y_hat = mode({f_theta(w_j)}_{j=1}^W)

B. Signal Conditioning & Preprocessing:
  - Adaptive Windowing: Window duration Tw = 0.08 s (Lw = 2048 samples at 25.6 kHz;
    Lw = 960 samples at 12.0 kHz). Hop size = 1.0 (non-overlapping).
  - DC Offset Removal: Each window is demeaned independently: x_w[n] = x_w[n] - mean(x_w).
  - Normalization Scale: Global scalar sigma_train = 3.8993436671993384 fit strictly on
    DC-removed source_train windows.

C. Stage 1: Operating-Condition Support Gate (src/support/source_support.py):
  - Evaluates telemetry c = [speed, load]^T.
  - 2D Delaunay Convex Hull: Evaluated when calibration points span full 2D space (dim=2).
  - Collinear Bounding Box Fallback: When telemetry points are collinear (e.g., SDUST where
    all source files have load = 0.0 kN, dim=1), Stage 1 evaluates independent 1D intervals:
      B = [s_min - delta_s, s_max + delta_s] x [L_min - delta_L, L_max + delta_L]
  - Adaptive Slack Formulation:
      delta_j = max(alpha_range * Delta c_j, delta_min)     if Delta c_j > eps_deg
      delta_j = alpha_degen * |c_j,center| + delta_min      otherwise
      where Delta c_j = c_j,max - c_j,min, alpha_range = 0.10, delta_min = 0.15,
      alpha_degen = 0.02, eps_deg = 1e-8.
  - Active SDUST Verified Bounds:
      Speed: [1400.0, 2600.0] RPM (source span [1500, 2500] RPM, slack = 100.0 RPM)
      Load:  [-0.15, 0.15] kN     (source load 0.0 kN, slack = 0.15 kN)
  - Early Exit: If telemetry is outside bounds, emits BOT with reason
    CONDITION_AXIS_OUT_OF_SUPPORT in 0.14 ms CPU latency.

D. Stage 2: Kinematic Order-Domain Spectral Envelope Gate (src/support/physical_envelope.py):
  - Support Subsampling: K = 16 uniformly spaced windows per recording are evaluated.
  - Order-Domain Feature Extraction:
      * Shaft rotation frequency: fr = speed / 60 Hz.
      * Order mapping: o_k = f_k / fr across orders [0, o_max], where o_max = 384.0.
      * 11 Logarithmic Spectral Descriptors per window:
          1. v_{w, 1}:  log total energy = ln(max(sum_k |X_w[k]|^2, eps))
          2. v_{w, 2}:  log RMS amplitude = ln(max(sqrt(mean(x_w^2)), eps))
          3. v_{w, 2+b} (b=1..8): 8 order bands across [0, 384.0] (width = 48.0 orders)
          4. v_{w, 11}: low-order energy for orders o_k < 5.0 (unbalance/misalignment band)
      * Recording descriptor: Coordinate-wise median across K=16 windows yields phi(x) in R^11.
  - ANOVA Feature Screening on Source Validation:
      Features retained if condition effect size eta_cond^2 >= 0.15 and fault effect
      size eta_fault^2 <= 0.45.
  - Tolerance Envelope:
      I_{r, k} = [mu_{r, k} - tau * sigma_{r, k},  mu_{r, k} + tau * sigma_{r, k}]
      calibrated on source validation with 25% energy mass percentile expansion.
  - Early Exit: If any screened feature falls outside regional envelopes, emits BOT with
    reason PHYSICAL_INCONSISTENCY in 5.40 ms CPU latency.

E. Decision Hierarchy:
    A(x, c) = g1(c) * g2(x, c)
    y_hat(x, c) = mode({f_theta(w_j)}) if A(x, c) == 1 else BOT

10. SCIENTIFIC INTERPRETATION & METHODOLOGICAL LIMITATIONS
================================================================================

1. Empirical Scope of Zero False Acceptance:
   The 0.0% false acceptance rate observed on SDUST and CWRU demonstrates that SPHARE-BD Final
   Version reliably rejects the evaluated operating speed, load, and bearing geometry shifts.
   It does not constitute a mathematical guarantee against arbitrary, unmodeled adversarial shifts
   whose physical signatures happen to coincide with the calibrated source envelope.

2. Selective Accuracy vs. Forced Accuracy:
   The 100.0% diagnostic accuracy reported on SDUST applies strictly to the 90.0% admitted
   supported recordings. Selective accuracy must not be equated to 100% forced classification
   accuracy, as the model exercised abstention on 3 marginal recordings in the IN stratum.

3. Foreign-Machine Rejection vs. Cross-Machine Diagnosis:
   SPHARE-BD rejected 100% of foreign CWRU records (75% at Stage 1, 25% at Stage 2). This demonstrates
   effective protection against false forced diagnosis, but represents an abstention rate of 100%.
   SPHARE-BD does not diagnose foreign machines without source calibration on that machine family.

4. Metadata Semantics:
   In CWRU evaluations, motor load is recorded in horsepower (HP), while SDUST load is stored in
   kilonewtons (kN). Numerical metadata was evaluated as stored. While 1-3 HP exceeded the [-0.15, 0.15]
   numerical threshold at Stage 1, the 0 HP condition passed Stage 1 and was strictly rejected by
   Stage 2 rotational order spectral physics.

5. Temporal Holdout Limitation:
   Evaluation recordings in eval_IN, eval_EDGE-1500, and eval_EDGE-2500 are later non-overlapping
   temporal slices ([839680, 1048576)) of the same physical testbed runs used for training,
   separated by a 2048-sample guard gap. They evaluate temporal stability under supported regimes,
   not unseen bearing installations.
